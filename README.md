# 吸血鬼爬行者出牌助手（Vampire Crawlers Card Advisor）

> **关于仓库名**：GitHub 仅允许 ASCII 字符作为仓库名，无法使用中文「吸血鬼爬行者出牌助手」。因此仓库地址保持为 `vampire-crawlers-advisor`，中文名称以此处标题为准。

《Vampire Crawlers（吸血鬼爬行者）》的单机打牌辅助工具：**只读**读取游戏运行时状态，实时给出本回合出牌顺序建议。

- 插件 GUID：`vampirecrawlers.advisor`
- 当前版本：**1.1.0**
- 形态：BepInEx 6（IL2CPP / x64）插件 + 独立置顶伴侣窗口（Win32 + GDI 自绘）

---

## 一、这个工具是做什么的

在对战中给出**本回合的最优出牌顺序**，而不是替玩家出牌：

- 读取当前法力、生命、护甲、连击数、连击阶梯、手牌、费用、回蓝、运行时伤害
- 读取每只敌人的血量、护甲、本回合意图与预计伤害
- 读取我方全部增益 / 减益状态
- 结合以上信息计算出一个可执行的出牌序列，并显示每张牌的评分与理由
- 把每局战斗记录到本地 JSONL，便于后续离线校准评分权重

**明确不做的事**：不自动打牌、不修改游戏数值、不写入游戏存档、不向游戏发送输入、不修改游戏文件。

---

## 二、算法：它是怎么算出牌顺序的

整体是「**动态规则引擎 + 回合内搜索 + 可解释评分**」，而不是神经网络。原因是卡牌局属于完全信息下的组合优化，规则可从游戏直接读取，搜索比黑盒拟合更准且可解释。

### 1. 动态生效值层

所有数值都以**游戏此刻实际生效的值**为准，不依赖静态卡牌数据库：

- 费用 = 配置基础费用 + 全部费用修正（遗物、临时、混乱、减免、临时免费）
- W（万能）牌：识别 `WildCostType`，按 0 费且可续连击参与计划
- 伤害：调用游戏的 `DamageEffect.GetDamageDescriptionValue(...)`，自动包含力量、遗物倍率、连击倍率
- 回蓝：调用 `GainManaEffect.GetModifiedEffectAmount(...)`，自动包含连击倍率（配置 3 × 连击 4 = 实际 12）

### 2. 连击优先的回合内搜索

1. 先问游戏 `PlayerModel.IsCardInCombo(...)`：手上哪些牌能接上当前连击；只要存在，首张必须从中选择，避免断连击。
2. 连击阶梯取自 `PreviousComboCardCost ± 1`（`ReverseCombo` 时递减），按阶梯逐张续接。
3. 当前无法续连击时，枚举所有可行的起始费用，模拟整段阶梯并取总分最高的一段。
4. 同一费用档位内取评分最高的牌。

### 3. 可解释评分模型

- 角色基础分：法力 / 武器 / 防御 / 经济 / 被动 / 功能 / 角色 / 负面
- 局面修正：生命比例、敌方本回合预计伤害、敌人数量、法力余量、连击数、回合阶段
- 回蓝净消耗：净消耗 ≤ 0 的牌获得额外权重
- 负面牌：游戏类型为 `Debuff` 的牌基础分 `-120`，不享受低费 / 0 费加成
- 特殊卡：万能 +10、已碎裂 −40

### 4. 后续学习路线（已开始落地）

- 每局写入本地 JSONL：局面、有效值、助手建议、实际出牌、战斗结果
- 支持「训练模式 / 沙盒模式」（`F10`），沙盒局只存档不参与学习
- 自动标记疑似「故意输」对局（多回合有牌不出），避免污染数据
- 后续用离线统计 / 线性或 GBDT 模型校准评分权重，运行时仍保持零依赖

## 三、它如何读取游戏内容

- 通过 **BepInEx 6（IL2CPP / x64）** 加载进游戏进程
- 用 **Il2CppInterop** 读取 `Nosebleed.Pancake.*` 命名空间下的运行时对象，例如：
  - `PlayerModel`：生命、法力、护甲、连击、回合、手牌、牌堆、出牌历史
  - `CardModel` / `CardConfig`：卡牌名称、费用修正、效果、碎裂状态
  - `EnemyEncounterModel` / `EnemyModel`：敌人血量、护甲、当前意图与预计伤害
  - `PlayerStats`：力量、成长、贪婪、诅咒等增益 / 减益
  - `Unity.Localization`：卡牌名称直接取游戏本地化文本，保证与界面逐字一致
- **只读**：只获取字段值和调用查询类方法，不调用任何会改变游戏状态的方法
- 伴侣窗口为独立进程内 Win32 窗口，不占用游戏画面、不抢占游戏焦点
- 本地日志只写入插件自己的目录：`BepInEx/VcAdvisorLogs/battles-YYYYMMDD.jsonl`

## 四、使用说明（简要）

### 运行环境

| 项目 | 要求 |
|---|---|
| 游戏 | Vampire Crawlers（Steam AppID `3265700`，Unity IL2CPP x64） |
| 插件框架 | BepInEx `6.0.0-be` 系列（IL2CPP 版，x64） |
| 依赖 | 无额外依赖（`cards.tsv` 已内嵌进 DLL） |

### 安装

1. 为游戏安装 BepInEx 6 IL2CPP x64 并启动一次。
2. 退出游戏。
3. 把 `VcAdvisor.dll` 放入 `<游戏目录>/BepInEx/plugins/`。
4. 重新启动游戏，日志出现 `Vampire Crawlers 打牌助手 v1.1.0 已加载` 即成功。

### 快捷键

| 按键 | 作用 |
|---|---|
| `F8` | 显示 / 隐藏伴侣窗口 |
| `F9` | 把窗口强制拉到屏幕右下角（找回窗口） |
| `F10` | 切换「训练模式 / 沙盒模式」 |
| `F7` | 游戏内叠加层（后备方案） |

### 界面

- 暗色哥特风配色 + 金色点缀，角色图标由 GDI 矢量绘制
- **首推出牌**：21px 大字 + 整行高亮底 + 金色箭头 + 分值行
- 其余出牌：圆形序号徽章 + 角色图标
- 不使用进度条 / 色条表达数值，数值一律以文字呈现

### 故障排查

日志：`<游戏目录>/BepInEx/LogOutput.log`

| 现象 | 处理 |
|---|---|
| 没有伴侣窗口 | 按 `F8`；或按 `F9` 找回 |
| 显示「未找到玩家对象」 | 正常：尚未进入对战 |
| `F8` 无反应 | 热键可能被占用，日志会提示注册失败 |
| 窗口被截断 | 内容已按屏幕高度封顶，可切「简化」模式 |

## 五、构建说明

### 环境要求

- **.NET SDK 8.0（必需）**，已验证构建环境为 `8.0.425`
- 项目目标框架仍为 `net6.0`，但请统一使用 8.0 SDK 构建（`dotnet --version` 应为 `8.x`）
- 已安装 BepInEx 6 IL2CPP 的游戏目录

### 修改游戏路径

`VcAdvisor.csproj` 中的 `GameDir` 默认指向：

```xml
<GameDir>d:\Steam\steamapps\common\Vampire Crawlers</GameDir>
```

可改成自己的目录，或用命令行覆盖：

```powershell
dotnet build -c Release -p:GameDir="D:\你的路径\Vampire Crawlers"
```

### 编译与部署

```powershell
dotnet build -c Release
Copy-Item .\bin\Release\VcAdvisor.dll "<游戏目录>\BepInEx\plugins\VcAdvisor.dll" -Force
```

> DLL 在游戏运行时被锁定，覆盖前必须先退出游戏。

### 项目文件

| 文件 | 作用 |
|---|---|
| `Plugin.cs` | BepInEx 入口、生命周期、伴侣窗口内容组装 |
| `GameState.cs` | 只读采集：玩家 / 敌人 / 手牌 / 有效费用 / 运行时伤害 / 回蓝 / 连击 / 回合 |
| `Scoring.cs` | 评分与回合内出牌计划编排 |
| `CardDb.cs` | 卡牌名称（游戏本地化接口）与角色分类 |
| `CompanionWindow.cs` | 独立置顶窗口：窗口消息、布局、GDI 绘制、图标、热键 |
| `BattleLog.cs` | 对局 JSONL 记录、沙盒标记、质量过滤 |
| `cards.tsv` | 内嵌卡牌补充名称表 |
